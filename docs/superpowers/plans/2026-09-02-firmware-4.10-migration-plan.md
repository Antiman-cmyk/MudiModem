# MudiModem — firmware 4.10 migration plan v2 (merged)

**Date:** 2026-09-02 · **Supersedes:** v1 of this file (same date). This is the merge of two
independently-produced plans:
- **Plan A** (this repo's session): full teardown of the official `e5800-4.10.0_release5-1092`
  image (sdat2img → debugfs), five deep-dive analyses, repo 4.8-coupling inventory.
- **Plan B** (external): built from live RG650V-**EU** E5800 output on 4.10 + its own firmware
  analysis; its spine is a **cellular compatibility/normalization layer**.

**Version:** MudiModem **2.0.0**. **Shipping posture: 4.10-only** (owner directive — no 4.8
compat shipped), BUT built on Plan B's normalization-layer architecture so the UI/LCD/tracking/
speedtest never see firmware shapes; a legacy adapter *could* be slotted in later without
touching consumers. ⚠️ Open policy question for upstream (kevinherzig/MudiModem): if upstream
insists on dual support, only the adapter layer grows — nothing else in this plan changes.
Keep a `legacy-4.8` tag/branch before the first 2.0.0 merge either way.

Provenance marks: 🟢 verified in-image by reading source / quoted minified JS · 🟡 strings/
symbols on ELF/bytecode · 🔵 Plan B live-box observation (EU unit) · 🔴 must pin on box in
Phase 0 before coding against it.

## 0. Merge verdict — what each plan got right, wrong, and missed

**Plan B claims cross-verified by Plan A's image evidence (now 🟢):**
- The 3-socket ws model and merged shapes (`websocket/cellular.lua` is plain source; §2).
- **`simcard[].dial_status` semantics**: the merge sets `simcard.dial_status = net.status`
  (the connection enum), and GL's own internet.js maps `{0:"active",1:"connecting"}[dial_status]`
  → **`dial_status == 0` = carrying data.** (An earlier sub-analysis claiming `===2` = connected
  was wrong; corrected.) Never read raw `network.dial_status` for this — it feeds only the
  modem-level `dial_enable` flag.
- **`cellular.network cell_info` triggers raw AT per call.** `libcm_network.so`'s exported
  `get_cell_info` has an *undefined dynamic symbol reference* to `quectel_get_qcainfo_signal`,
  plus error strings `get_cell_info_ubus: qcainfo failed bus=%s slot=%d sub_id=%d` — the handler
  drives QENG/QCAINFO on the shared AT channel every call. The 1.7.0 collectd's 4 s `cell_info`
  poll is a continuous AT load; the old doc line "reads cellular_manager CACHE — NEVER raw AT"
  is **false on 4.10** and must be corrected everywhere.
- **GL ships its own periodic signal collector**: `libcmcollect.so` registers ubus
  `cellular.collect` with `get_signals`/`get_all_signals_json`, timer-driven
  (`collect_signal_data_all_bus`), configured by a runtime `/etc/config/collection.json`
  (not in the image — read it on box); `modem.get_signals {bus,slot,time}` is what GL's own
  modemsignallog + cellular-detail poll (10 s). Prime candidate source for our high-frequency
  layer.
- Minimal SIM switch payload `{bus, current_sim}` — GL's own `handleUseSim` sends exactly that 🟢.
- `set_band_config` payload shape 🟢 (verbatim in cellular-detail); response extras
  (`band_filter_mode` echo, `supports_band`, band_list only when filtering) 🔵→pin.
- RAT enum family split: 4/41 = LTE-family, 5/51 = NR — corroborated by GL's
  `formatBand {4:"B",41:"B",5:"n",51:"n"}` and `hasRssi ∈ [4,41,51]` (SA has no RSSI — physics
  agrees with 5=SA, 51=NSA). Labels `41="LTE+"`, `2/3` mappings 🔵→pin.

**Plan B corrected/challenged by Plan A:**
1. **It missed the push bus.** `gl-ngx-session` (plain lua-eco source) exposes
   `ubus call gl-session notify {name,data}` → broadcast to every subscribed web client, plus
   `has_websocket`; `cellular_manager` itself pushes `cellular.modems_status`/`networks_info`
   through it 🟡. So the main UI needs **no** `get_latest` RPC and no incremental `get_history`
   polling: collectd publishes `mudimodem.collect` samples over the same bus, and a tiny
   `/usr/share/gl-ngx/websocket/mudimodem.lua` snapshot module serves the on-subscribe seed.
   Plan B's §12 `get_latest` idea is superseded (may still add as a trivial fallback).
2. **It missed that `gl_modem` is no longer a daemon** (now a one-shot CLI; `cellular_manager`
   spawns `/usr/bin/modem_AT -B <bus> -P <port>` per bus and polls through it; `/dev/smd9`
   gone 🟢/🟡). The AT tool's `gl_modem` SIGSTOP/SIGCONT machinery targets a nonexistent
   process — delete it (keep flock + drain + strict terminator). verify.sh 8e replaced.
3. **It missed battery entirely.** 4.10's `quec_battery` (START=04, procd respawn, charge-IC
   hardware watchdog via `/etc/ChargeIC_wdt`) actively owns `vreg/charge_en/hiz_mode/ichrg_curr`
   on the same sysfs nodes `glbattlimit` writes 🟢/🟡 — a duel test decides port vs honest
   feature gate (§9).
4. **It under-covers LCD/packaging/docs**: gl_screen is procd `respawn 1 5 -1` (never
   bare-kill), GL 4.10 added Display Management UI + timedtask LCD schedules that no-op while
   our renderer owns the panel (must be documented in-UI); install/uninstall/deploy/sysupgrade
   file-list sync, firmware floor guard, version 2.0.0 — all Plan A material kept (§9–§11).
5. **§22 two-phase apply (raw-AT live + GL durable on Keep) is challenged.** Single-path
   `set_band_config` is fail-closed *and* durable **by construction** (a failed write changes
   nothing; a successful one is already persisted; Keep = delete PENDING, which cannot fail),
   and it avoids a new 4.10 hazard: GL's manager owns the config store and may re-apply it over
   a divergent raw-AT state mid-countdown. Plan B's **fail-closed principle is fully absorbed**;
   whether live-apply must stay raw-AT is decided by Phase 0 #5 (does `set_band_config` apply
   immediately? does it redial/disrupt?). Default: single-path. Fallback: Plan B's two-phase
   with its §21 fail-closed Keep, verbatim.
6. §16's 6-socket superset menu is moot under 4.10-only; ship 3 GL sockets + `mudimodem.collect`.
7. Plan B's §17 (`status {bus:"cpu"}` → flat, `st.current_sim_slot`) 🔵 is the likely
   resolution of Plan A's hard contradiction (ws lua + internet.js expect `modems[]` from the
   *no-args* call; issue #5 observed flat): **working hypothesis — no-args = wrapped
   `modems[]`, bus-scoped = flat.** Still 🔴 Phase 0 #1: capture BOTH arg forms + real `/ws`
   frames. The tolerant `unwrap` helper is kept regardless — as intra-4.10 robustness, not as
   4.8 compat.

**Adopted from Plan B wholesale** (Plan A's v1 lacked them): the normalization layer as the
spine; the formal data-contract doc; the multi-carrier `signals[]` sample schema with PCC/SCC
roles; the two-cadence collector; no-service sentinel normalization; tracking topology keys;
CA/multi-serving Bands UI; NR-ARFCN/LTE-EARFCN correctness + shared band-metadata table
(EU + NA); shared `cellular_compat.py`; the fixture/test matrix and perf budgets; the FD-detach
hardening as a separate PR; the "passive reads are silent" rule generalization.

## 2. The formal 4.10 data contract — new doc `docs/cellular-api-4.10.md`

Single source of truth, written from Phase 0 captures (both NA and EU units if possible).
Contents (structure per Plan B §1, semantics as verified):

- **`cellular.modems_info`** — passthrough of `cellular.modem info`: `modems[]`
  `{bus, name, vendor, type (0=built-in), band{LTE[],NR-SA[],NR-NSA[]}, sim_slot_num,
  slot_support_esim[], supports_ip_type, …}`.
- **`cellular.modems_status`** — merged (modem ⋈ sim ⋈ network status): `modems[]`
  `{bus, current_sim_slot, slot_switch_status, slot_switch_enable, status, dial_enable,
  simcard[]{slot, status, dial_status, technology, strength, type, apn, iccid, name,
  pin_counter, traffic_total, traffic_threshold, unit}}`.
  **Documented rule: `simcard[].dial_status` is `cellular.network status→networks[].status`
  re-keyed; `0=connected/carrying data, 1=connecting` (GL's own mapping). Raw
  `network.dial_status` must never be consumed for connection state.**
- **`cellular.networks_info`** — merged (network ⋈ sim info): `networks[]`
  `{bus, slot, carrier, apn, apn_list[], iccid, imsi, mcc, mnc, phone_number, ip_type,
  network_mode, network_interface}`. **SIM identity needs no extra RPC/socket** — delete the
  "identity from `sims_info`" assumption everywhere.
- Dead names (subscribing yields nothing): `cellular.sims_info`, `cellular.sims_status`,
  `cellular.networks_status` (commented out in `websocket/cellular.lua`).
- **`cellular.network cell_info {bus,slot}`** → `{network_type, tac, cell_id, signal[]}`,
  per-CC rows `{ca, band, earfcn, pci, bandwidth(/ _ul/_dl), rsrp, rsrq, sinr, rssi,
  rsrp_level, …}`; `signal[0]≈PCC`, others SCC (QENG→PCC, QCAINFO→SCCs). **Cost note in the
  doc: this call executes QENG/QCAINFO — rate-limit it.**
- **RAT enum (one table, three languages generated from it):**
  `2→"2G", 3→"3G", 4→"LTE", 41→"LTE+", 5→"NR5G-SA", 51→"NR5G-NSA"` (4/5/51 verified; 2/3/41
  labels pinned in Phase 0 #2).
- **No-service sentinels** (🔵→pin): `network_type=0`, empty `cell_id`/`tac`, metrics
  `-32768`, band/earfcn/pci/bandwidth `0` → all normalize to `null` / `signals: []`.
- `gl-session` contract: `notify {name,data}`, `has_websocket`, `call {module,func,params}`;
  ws subscribe/snapshot protocol; `mudimodem.collect` (ours) documented alongside.
- Band API: `modem.get_band_config {bus,slot}` →
  `{band_enable, network_mode:"AUTO"|"NR5G"|"LTE", band_filter_mode(echo), supports_band,
  band_list?}`; `set_band_config` sends ONLY
  `{bus, slot, band_enable, network_mode, band_list{…}}` (no `band_filter_mode` unless the box
  proves it required); mode `LTE` ⇒ NR lists emptied (GL's own rule); never send an empty list
  for a RAT whose policy is empty.

## 3. Target architecture — the normalization layer (Plan B §50 + Plan A push bus)

```
        GL 4.10 APIs (ws sockets · ubus · modem.* RPC · raw AT policy reads)
                                   │
                     ┌─────────────┴──────────────┐
                     │  compat / normalization    │   Python: /usr/lib/mudimodem/cellular_compat.py
                     │  (single place that knows  │   Lua:    helpers in src/rpc/mudimodem
                     │   firmware shapes)         │   JS:     cellModel() in mudimodem.js
                     └─────────────┬──────────────┘
                                   │  normalized state
        ┌──────────────────────────┼───────────────────────────┐
        ▼                          ▼                           ▼
  ws status model            RF collector                 config RPC
  (SIM/carrier/identity/     (signals[] samples →         (Bands/Lock/APN/
   registration/failover)     jsonl + latest.json +        Failover via GL APIs
        │                     collectd.sock +              + AT policy reads)
        │                     gl-session notify push)           │
        └──────────────┬──────────┴────────────────────────────┘
                       ▼
        Main UI · Tracking · LCD · Speedtest · Console labels
```

- **ws = status; collector = RF; no cross-reading** (Plan B §13). The frontend's one
  `cellModel()` computed adapts the three sockets; serving-cell RF comes only from
  `mudimodem.collect` push / history backfill. `networks_info[].cell_info` reads (4.8) die.
- **Normalized sample schema** (Plan B §2, adopted): full `signals[]` with
  `{role:"PCC"|"SCCn", ca, network_type, rat, band, earfcn, pci, bandwidth_mhz, rsrp, rsrq,
  sinr, rssi, rsrp_level…}` + top-level `{t, slot, registered, carrier, rat, network_type,
  cell_id, tac}` + **flattened primary/PCC aliases** (`band, mode, id, tx_channel,
  dl_bandwidth, rsrp, rsrq, sinr, rssi`) so tracking/LCD/speedtest/strip keep working
  unmodified while CA-aware consumers read `signals[]`.
- Shared Python helpers `cellular_compat.py` (deployed `/usr/lib/mudimodem/`): `unwrap_modem`,
  `normalize_network_type`, `normalize_metric`, `normalize_cell_info`, `normalize_signal`,
  `normalize_no_service`; consumed by collectd + speedtest (ends the copy-paste divergence —
  supersedes the "each script self-contained" convention, documented). Lua gets small local
  equivalents (`modem_obj`, `active_slot`); JS gets `cellModel()` + one `formatBand(signal)`
  (rat-driven `B`/`n` prefix — kills the scattered `isNR ? "n" : "B"`).

## 4. Collector redesign (`mudimodem-collectd`) — the load fix + the push

1. **Two cadences** (Plan B §5): high-frequency **signal** layer ~10 s; low-frequency **cell
   topology** (`cell_info` → cell_id/TAC/PCI/bands/EARFCN/CA/bandwidth) ~20 s; merged into one
   normalized sample. Even the conservative fallback (everything from `cell_info` at 20 s)
   cuts AT traffic ~80 % vs today's 4 s.
2. **Prefer GL's built-in collector** for the signal layer: Phase 0 pins
   `ubus -v list cellular.collect`, `/etc/config/collection.json` (runtime-generated), and
   `modem.get_signals` shapes/cadence; if `cellular.collect`/`get_signals` serves cached
   samples, collectd consumes it and issues **zero** extra AT for signal metrics.
3. **Push, don't poll** (Plan A): each sample → `ubus call gl-session notify
   '{"name":"mudimodem.collect","data":<sample>}'`, gated on `gl-session has_websocket`;
   ship `/usr/share/gl-ngx/websocket/mudimodem.lua` returning
   `{collect = <latest sample>}` as the subscribe-time seed; menu `global_sockets` =
   `["cellular.modems_info","cellular.modems_status","cellular.networks_info","mudimodem.collect"]`.
   The main chunk drops its 10 s `get_history` incremental poll (history RPC remains for
   window backfill + tracking + battery).
4. **No-service normalization** (Plan B §10): sentinel payloads → `null`s / empty `signals`;
   a no-service sample still advances cursors but plots as a gap and **never** fabricates
   `cell "" / band 0 / mode 0` transitions.
5. Sample schema per §3; `carrier` sourced from the merged status/info calls (pin in Phase 0
   which of `cellular.sim status` / `network info` carries it now).
6. Battery sampler unchanged (kernel-provided sysfs; Phase 0 re-captures attrs).
7. Perf budget wired into verify.sh (Plan B §44): assert configured cadences; target
   ≈6 signal reads/min and ≤3 `cell_info`/min (vs 15/min today); optional debug counters
   (reads/min) in `latest.json` for the budget check.
8. Speedtest (`tools/mudimodem-speedtest.py`): prefer `latest.json` when age < 30 s; only
   probe `cell_info` itself when the collector is stale/absent (Plan B §29); same compat lib.

## 5. Backend (`src/rpc/mudimodem`)

1. **`resolve_active()` rewritten** (Plan B §17 + Plan A): `cellular.modem status
   {bus="cpu"}` → flat `current_sim_slot` (hypothesis pinned in Phase 0 #1; tolerant unwrap
   kept); PLMN from `cellular.sim info` (server-side, still exists). **Every** consumer —
   `get_bands`, `set_bands`, `get_lock`, `set_cell_lock`, `clear_cell_lock`, `scan_cells` —
   uses it; the `slot=nil → 1` fallback dies (SIM2/eSIM must never be mis-targeted, Plan B §23).
   `resolve_sub_id` keeps PLMN probing; "never send sub_id=0" stands until the new baseband
   re-proves it.
2. **`get_bands`**: supported = `modems_info.band` (ws-mirrored server-side via
   `cellular.modem info {bus}`); config+mode = `get_band_config {bus, slot}` (per-SIM; replaces
   `get_feature_config`, the duplicate-`network_mode` hack, and the mode AT read); policy +
   capability = raw AT (`policy_band`/`ue_capability_band`) via `modem.CPU.AT` + sub_id —
   only on Bands-page entry (low frequency, fine). Three layers stay front and center.
3. **`set_bands` — single-path, fail-closed, durable** (merge decision §0.5): snapshot =
   previous `get_band_config`; write = `set_band_config` (exact GL payload, §2 rules); success
   → arm watchdog + PENDING as today; failure → nothing changed, error out (fail-closed by
   construction). `confirm` = delete PENDING (cannot fail); watchdog/`revert_now` restore the
   snapshot via `set_band_config`; panic = `{band_enable:false, network_mode:"AUTO"}` (pin the
   `band_enable:false` = "no filtering" semantics, Phase 0 #5). Deleted: Path-B
   `set_feature_config`, `gl-stale`, `get_all_config` slot_feature parsing, hardcoded AT
   band lists as primary restore (kept only as a labeled last-resort branch in
   `mudimodem-revert`). *Fallback design if Phase 0 #5 disqualifies live-apply-via-API:* Plan
   B's two-phase (AT live apply/revert + `set_band_config` at Keep) with its §21 fail-closed
   Keep (persist fails ⇒ PENDING + watchdog stay armed, error returned, countdown expiry
   auto-reverts).
4. **Cell lock**: keep glc `modem get/set/scan_cell_tower`; adopt the 4.10 tower payload
   (`scs, tac, srxlev, squal, bandwidth, country, carrier, freq, pci, cellid, band…`); active
   slot via `resolve_active()`; `get_lock`'s serving-cell read prefers `latest.json` when
   < 30 s old, QENG only as fallback (Plan B §24; the EN-DC multi-line QENG parser from 1.6.0
   stays for that path). Phase 0 #6 re-checks whether 4.10's unlock restores `mode_pref`
   itself (GL now owns `mode_pref,LTE:NR5G` + `nr5g_disable_mode` templates); keep or delete
   our AUTO-restore triple accordingly.
5. **SIM switch**: split (Plan B §26) — manual switch sends minimal
   `{bus, current_sim}` (GL's own pattern); failover settings keep the
   `get_slot_failover_config → RMW → set` path with `slot_type` carried through.
6. **APN**: RMW stays (Plan B §27) on the slimmed 4.10 profile
   (`apn, protocol, auth, username, password, dial_number, ip_type:Number, roaming, rrc_seg,
   ttl, ttl_ipv6, hl, mtu`); delete the band-preservation logic + its stale comment (band left
   `set_sim_config`).
7. **AT console**: transport unchanged (`/dev/at_mdm0`, flock, drain, terminators); delete the
   `gl_modem` SIGSTOP/CONT + startup-recovery machinery (process gone); verify.sh 8e →
   assert `modem_AT` present and running.
8. **Silent-RPC rule generalized** (Plan B §28): every background/passive read
   (version check, history, metadata, passive SIM/failover refresh) goes through
   `rpcSilent`; only user-initiated writes surface errors. (Existing 📌 rule, now enforced
   repo-wide.)

## 6. Frontend

1. **`cellModel()` normalization** in `mudimodem.js` — sole consumer of the 3 sockets + push;
   SIM cards per Plan B §14 (`simcard[]` for registration/`dial_status==0`/technology/APN;
   `networks_info` for imsi/iccid/mcc/mnc/phone_number/carrier/apn_list); identity is
   eventually-consistent — render "—" until the next push, **no** compensating RPC polls
   (delete any `fetchSimStatic`-style timers, Plan B §15).
2. **Serving/RF strictly from the collector** (push-fed; `serving()` from
   `networks_info.cell_info` deleted). Strip: seed from `get_history` window once, then live
   via `mudimodem.collect`.
3. **Multi-serving Bands UI** (Plan B §8): `servingGroup/servingBand` →
   `servingBands()` returning `[{group, band, role}]` from `signals[]`; SA = one chip; NSA =
   LTE anchor + NR chips; LTE-CA = several `B` chips; `selected` and `serving` remain distinct
   visual states. Mode control = `network_mode` tri-state (AUTO/NR5G/LTE), GL's force-empty
   rule mirrored; reset-to-default = `band_enable:false` (the force-resend note machinery
   dies).
4. **Tracking** (`mudimodem-tracking.js`): topology key
   `[slot, cell_id, network_type, pcc.band, pcc.pci, pcc.earfcn]`; null/no-service never emits
   a handover; SCC add/remove is *not* a handover (optionally a separate "CA changed" event,
   else no event) (Plan B §11). Menu JSON's dead `global_sockets` removed; any legacy
   `cell_info` live-fallback removed (Plan B §36).
5. **Console chunk**: labels (active slot / carrier / technology) from the shared normalized
   model — no private `modems[0]` reader (Plan B §37).
6. One `formatBand(signal)` helper shared across Bands/Tracking/strip (Plan B §34).

## 7. RF metadata correctness (Plan B §31–33, adopted; fixes CLAUDE.md open question #4)

- **NR**: proper `nr_arfcn_to_mhz(n)` per the 3GPP 38.104 global raster
  (<600000: 5 kHz; 600000–2016666: 15 kHz + 3000 MHz offset; ≥2016667: 60 kHz + 24250 MHz) —
  replaces any `arfcn*5/1000`-style shortcut (627264 → 3408.96 MHz).
- **LTE**: band-aware `lte_earfcn_to_mhz(band, earfcn)` from TS 36.101 (`F_DL_low` +
  `N_Offs-DL` per band); if the table is incomplete for a band, show the raw EARFCN rather
  than a wrong MHz.
- **Band metadata extracted to one source** — `src/data/bands.json`
  (`{NR:{"78":{freq_label,"default_scs"}…}, LTE:{…}}`) covering **both NA and EU** RG650V sets
  (EU: LTE 1/3/5/7/8/20/28/32/38/40/41/42/43; NR 1/3/5/7/8/20/26/28/38/40/41/75/76/77/78);
  JS/Python tables generated or loaded from it; a test asserts three-way consistency.
  (Context: Plan B's unit is RG650V-**EU** — the repo's NA-centric tables are now provably
  incomplete. The at-library's `verified:["RG650V-NA"]` entries correctly render "nobody yet"
  on EU; EU verifications can come later.)

## 8. Process hygiene — FD-detach hardening (Plan B §35; separate PR, not 4.10-coupled)

Detached children spawned from nginx Lua via `os.execute("… &")` (`mudimodem-revert` watch,
speedtest launch, self-update, glbattlimit via hotplug path) can inherit nginx's listening
FDs (443) and pin them across nginx restarts. One shared
`/usr/lib/mudimodem/mudimodem-detach` closes inherited sockets then execs the child; all four
call sites switch to it. Own commit/PR for reviewability.

## 9. Battery (Plan A; Plan B silent here)

Sampler: unchanged pending Phase 0 #9 sysfs capture (attrs are kernel-owned; same 5.15.170
line — the "attrs are gone" claim was method-invalid). Charge limit: on-box duel —
apply a limit, watch whether `quec_battery` (respawning, watchdog-armed) restores
